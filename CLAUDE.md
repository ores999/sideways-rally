# Sideways Rally

A browser rally game in a single HTML file. It has 5 stages (each also in reverse, at night and in the rain), a daily generated stage, rallies, challenge links for friends, live online rooms (race friends at the same time), 7 classic rally cars, a custom WebGL2 renderer, a physics model, and a co-driver that reads pace notes. There are no dependencies and no bundler: `build.py` concatenates the sources.

## Working with the owner
- The game is in **English** (UI, notes, car sheets). The owner speaks Spanish (Argentina). Reply in Spanish and use voseo.
- Cars use their **real names** (the owner asked for this; they used to be parodies like "Fjord Foca"): Ford Focus RS WRC, Subaru Impreza WRC, Mitsubishi Lancer Evo VI, Lancia Delta HF Integrale, Peugeot 205 T16, Audi Sport Quattro S1, Toyota Celica GT-Four, plus the bonus Volkswagen Saveiro Cross (`saveiro`, see Game modes). The make is lettered on the livery, `note` in `CARS` is the one-line blurb under the name in the garage, and the internal ids (`foca`, `impressa`, `lancha`, `delta`, `pejo`, `kwattro`, `selica`) stay as they are because saves and settings are keyed on them. Sponsors on the liveries are still made up.
- Effects should be noticeable without looking fake ("que se note pero que no se vea trucho"). Keep everything subtle.

Wheels are smoothed at 30°. src/world.js      WORLD: stage palettes (VIS), colour grading, terrain/road meshes, trees, ground cover, props
src/net.js        NET: minimal Phoenix-channel client for Supabase Realtime (broadcast + presence over one WebSocket, heartbeat, reconnect with backoff)
src/game.js       game loop, UI, input, audio (per-car engine synthesis), co-driver, camera, suspension visuals, effects, HUD, online rooms
dist/test.html    standalone page (with doctype). Open this to play locally
dist/sideways-rally.html  same without the doctype (the claude.ai artifact host adds it)
test/             node physics tests + python Playwright screenshot/flow tests

## Game modes and saves (game.js, core.js)
- **Stage keys** name a road and how it is run: `pine`, `pine-r` (reverse), `pine-night`, `pine-r-rain`, …, and `daily-YYYYMMDD`. `C.stageDef(key)` builds/caches the stage object (`key`, `id` = biome/VIS id, `kind`, `rev`, `cond`); `C.buildWorld(stageOrIndex)` takes either. Everything saved is keyed on the key: `pb.<key>.<car>`, `medal.<key>`, `chal.<key>`.
- **Reverse**: `buildTrack` builds the forward road, then flips the arrays (same place in the world, so the same scenery noise), negates curvature, mirrors notes and walls, and rebuilds jumps/crests facing the new direction. Mesa's gorge walls are data now (`walls: [[from, to, off]]` as fractions of L); Dark Pines' tree rows are `rows: true`.
- **Conditions**: `cond: 'rain'` lowers grip (gravel ×0.88, tarmac ×0.8, frost ×0.96 = blizzard). Visuals come from `WORLD.visOf(st)` (`nightVis`/`rainVis` derived from the biome palette): night = moonlight, stars, headlights strong (`hl`); rain = overcast sky deck (`u_ovc` in SKY_FS), wet road with puddles (`u_wet` in LIT_FS mode 1, sheen in mode 9), rain streaks (`R.lines` + `LN_FS`, `updateRain`), spray instead of dust (`SURF_WET`), rain/water hiss audio; frost rain = blizzard (heavier, windblown snow).
- **Daily stage**: `dailyStage(ymd)` → `genSegs` (corner/straight/jump/crest mix like the hand-made stages, biome rotates by day) validated by `selfClearance(T) >= 34` m (the road never comes back closer than that to itself more than 140 m along it; the hand-made stages measure 32–41). 30 days in a row: 0 AI hits.
- **Best times** per stage key and car, ghost stored compactly (`packGhost`: quantised 2 cm / 1 mrad, second differences, zig-zag varints; ~11 KB base64 vs ~35 KB raw float32). Old `pb.<id>` entries migrate to the car that set them. `stageBest(key)` = record across cars.
- **Challenges**: `makeChallengeLink(run)` → `#c=` + base64url( flag byte, [deflate-raw]( u16 header length, JSON header {v,k,c,t,s,n,L,d}, packed ghost ) ); ~3 KB for a 1:45 run. `checkChallengeLink` reads it on load (and on `hashchange`), validates (stage exists, car, time, splits, track length `L`, ghost length vs time), stores `chal.<key>`, shows the banner. The challenger's ghost is red; delta, splits and results compare against it first (then your best, then the rival). Names go through `cleanName` and are only ever set as text.
- **Rally**: `RALLIES` (4 itineraries), `FIELD` (8 drivers with a skill factor). A driver's stage time = rival time on that stage (same car as yours) × skill × (1 ± ~1 %) + the odd 8–32 s incident, seeded per rally. One go per stage: starting a stage of the rally again adds 10 s (`rally.pen`). State in `store 'rally'`, best result per itinerary in `rallyBest.<id>`.
- **Driver name and leaderboard**: a browser with no `settings.name` gets the "Who's driving?" overlay (`#welcome`; the chip under the logo reopens it). The first name given takes over the bests this browser already had (`seedBoard`, flag `settings.boardSeeded`); renaming moves your own rows (`renameOnBoard`). The board (`store 'board'`: `{n, k, c, t, s, d, f}`, one best per driver/stage/car, `f` = came from a link) gets every finished run, every challenge received, and "Share my times" links (`#b=` + base64url(flag, [deflate](JSON {v, n, e: [[k, c, t, d]]})), ~180 chars for a few times). **Online**: `ONLINE = { url, key }` in game.js (Supabase project URL + publishable/anon key; schema and policies in `online/supabase.sql`, steps in `online/README.md`). When set, `onlineSync` posts your bests not yet sent (`store 'sent'`, all of them the first time) to `/rest/v1/times`, and `renderTimes` fetches `/rest/v1/best_times?stage=eq.<key>` (cached 30 s) and merges it with the local board. Empty config = local only. The board groups by road (`mapKey`: stage and direction), not by conditions: day, night and rain times share a table, night/rain rows carry a tag. It shows in the right panel on every tab except Car (`#gTimes`; `#timesInline` under the stage list on narrow screens) with stage and car filters, plus the AI rival's time for the loaded stage. There is no server: friends' times only arrive through links.

A white Saveiro Cross pickup (`pickup` shape: open bed built by `pickupBed` inside an extruded body whose bed-top edge is left open (`bed` flag on profile points), black liner, gold bed-rail caps, roof bars, two speaker boxes facing back with gold rings; the cones are their own mesh `spk`, pushed out by `spkPump()` on each kick), 560 hp AWD, and exaggerated on purpose (owner: "que doble como nada y que frene muy bien"): tyre 1.75, frontGrip 1.12, ClA 2.4, brake 2.6, agility 1.6, inertia 0.75, cgH 0.38. 100–0 km/h in 24 m on gravel / 20 m on tarmac (rally cars 44 / 35 m), 1.9 g / 2.45 g at full lock (rally cars ~1.0 / 1.25 g). ## Physics: car character (core.js `feel`)
- Each car has `feel: { lag, kick, ayc, push, twitch }` and a `character` blurb (garage). `lag`: the turbine spools with exhaust flow, so below the power band it builds slowly (`flow` in `dynamics`). `kick`: torque uses `boost^kick`, so part spool holds back and the boost arrives late and hard. `ayc`: throttle + steering adds yaw (Evo AYC 0.9, Focus/Impreza active diffs), fading once it slides. `push`: front lateral grip drops a little under power (Quattro's heavy nose). `twitch`: scales yaw damping and the spin catch (`calm = 2 - twitch`; 205 1.2, WRC cars 0.85).
- Measured: time to 90 % boost from 60 km/h in third: Focus 0.29 s, Quattro 1.14 s (was 0.87), 205 0.89 s (was 0.70); `P.spec.lag` is shown on the sheet. Full-throttle slip in `hmetrics`: Evo 11°→16°, Quattro 11°→9°. AI times moved < 0.5 s and `sim.js` stays at 0 hits/resets on all stage variants.

## Audio additions (game.js)
- Buses: car sounds → `A.car` (gain by distance from the camera, `A.carLp` air absorption, `A.carPan`) → master; world sounds → `A.env` → master; both feed `A.revIn` → `A.conv` (stereo IR generated per biome by `buildReverb`, `REVERB` table: early reflections, tail, damping, Red Mesa's far-cliff echo) and the car feeds `A.slap` (40–50 ms feedback delay: strong in the gorge, a little along Dark Pines' tree rows). Onboard camera sends less. `burst`/`toneAt` take a destination (default `A.car`); the countdown beeps go to the master.
- Doppler: `A.dopp` from the car's speed relative to the camera scales the engine `rpm` param and the turbo whistle (≈1 on the chase cameras, a real fly-by on the TV camera).
- Gravel: a second `crunch` worklet (`A.sp`) for stones in the wheel arches (rate from speed, slip, wheelspin; louder onboard) and `sfx.stone()` ticks/knocks under the floor. Handbrake thunk. Gear whine louder on the overrun.
- Crowd: sparse claps (`crunch` at 25–200/s with a 12 ms decay, `A.cl`; a dense click rate sounded like gravel), formant voices (`A.vox`), level and side from fans near the camera and how excited they are (`f.jump`), `sfx.whistle` and `sfx.horn` (air horn) while the car passes. Silent in the menu.
- Ambience: gusting wind (the menu keeps only a soft breeze), birds (`sfx.bird`, day), crickets as scheduled three-pulse chirps with rounded envelopes (`sfx.cricket`, night; square-wave AM sounded like electrical buzz), a hawk over Red Mesa, distant thunder in the rain (`sfx.thunder`). A continuous leaves hiss was tried and dropped (read as interference). Pausing mutes everything (`A.pz`).
- Levels measured live (analyser on the master, before the compressor): RMS 0.05–0.065 / peaks 0.2–0.35 chasing, ~0.02 on the TV camera; no clipping.
- Rivals in online rooms have engine voices of their own: see "The others' engines" under Online rooms.

## Rendering (gl.js)
- Instanced meshes, stride 11 per instance: `x,y,z,rot, sxz,sy,variant,0, r,g,b`. `a_i1.z` shifts the atlas u (ground cover variants).
- Lit shader modes: 0 vertex colour, 1 procedural road, 2 alpha-tested texture, 3 rock/props (broad noise, strata bands, speckle and hairline cracks keyed on world position), 4 emissive, 5 car livery (tex × vertex colour; plus metallic paint grain and sparse sun-catching flakes keyed on model-space `v_lp`, so they ride with the car), 6 decal (contact shadow), 7 ground cover (alpha-to-coverage, distance fade), 8 foliage (needle streaks along each face using a coordinate across the face `fu`, clumps and bright tips; bark furrows/knots on trunks (flagged by `v_uv.y < -0.5` and a dark colour); cactus ribs and spines (flagged by spec 0.02); a glow when the sun is behind; used by trees, cacti, shrubs and hay), 9 ground (terrain, verge strips, snow banks: broad variation + hue patches + two layers of a tiling detail texture, bump from its luminance).
- Ground detail textures (`groundDetailCanvas` in world.js, 512², linear RGBA8, repeat, mipmaps, aniso 8, made per stage and sampled at 1/3.4 m and 1/1.17 m rotated): pine = grass blades and clover dots, forest = needle litter, twigs, moss and pebbles, mesa = wind ripples (crest + shadow lines) and grain, frost = drifts, faint ripples, crust and glints. Neutral grey 128 means no change; the shader multiplies albedo by `d1*d2*4`. To add a stage, add a branch there. `R.texture(canvas, { repeat, linear })` takes the options. The verge strips take the colour of the terrain vertex nearest to their outer edge (`W.TC`), so they melt into the ground.
- Livery weathering is baked into the atlas (dust behind the wheels, tar/stone speckle along the sills, chips on the leading edges, scratches; per-car deterministic) on top of the dynamic `dirt` uniform. The reflection environment (`envRefl`) now includes the warm haze lobe around the sun.
- Far scenery (`farGeo`): Red Mesa's buttes (`butte()`): an 18-point irregular outline (spurs and the odd bay, carried straight up the cliff), a concave apron + scree, 3–4 strata bands from `VIS.mesa.strata`, a darker caprock that overhangs a little, and a flat top; kinds `mesa` (elongated), `tier` (a second smaller tier on top) and `butte`. Slender spires were tried and read as chimneys from that far. The other stages get procedural low-poly mountains (rings of jittered points under an off-centre peak, darker at the foot, paler rock higher up, snow on top) in two rows; the outer row is taller and hazier. Each spoke keeps its bearing and every ring reaches at least 0.16 w further out than the one above: with independent random radii a ring could tuck inside the next, folding the foot under into a dark, flat-topped "wall" facing away from the sun (that was the dark band on Pine Ridge's horizon).
- Far height fog: the far mesh is drawn with fog [380, 3200] but also `fogLo` = [stage fog near, far, ramp, ground y] (`u_fogLo`): near the ground it takes max(far fog, 0.8 × stage fog), easing to the far fog over 100 m (mesa) / 110 m (others) of height. Without it the terrain was pure haze beyond the stage fog while the buttes stood out clear above it, so they looked like they floated.
- Shadows: two cascades side by side in one 4096×2048 depth atlas (`beginShadow(0)` near, `beginShadow(1)` far; cascade 0 clears the atlas). In game.js, near = 32 m square about 7 m ahead of the car (~1.5 cm a texel), far = 140 m square 30 m ahead. The lit VS writes `v_sp`/`v_sp2` with a normal offset of ~1.2 texels per cascade (`env.shNo`), plus a small constant bias. `shadowF` blends near→far at the near cascade's edge, fades the far one out at its own edge, and filters with 12 rotated Poisson taps (`PD`, each a hardware 2×2 compare, `textureLod` because the loop branches). The first four taps sit on the rim ~90° apart; if they agree the other eight are skipped (only penumbrae pay for twelve; ~3 % of the frame). Atlas size (1024 vs 2048) and depth format (16/24/32F) made no measurable difference.
- `spec` (vertex colour alpha) drives gloss: Fresnel sky reflection (`envRefl`) + sun glint. `spec >= 0.75` = bare metal.
- HDR path: `R.beginScene(w,h,settings.post)` → MSAA RGBA16F → resolve → bloom chain (dual filter) → `R.endScene(E.grade)` composite with ACES, per-stage grade (lift/gain/sat/contrast/vignette in `VIS[stage].grade`). With no float buffers, or with the "Glow and colour grading" option off, the shaders tonemap directly (`u_hdr`).
- Tyre tracks use multiplicative blending (`DST_COLOR, ZERO`).
- Culling: `setLitFrame`/`beginShadow` load the pass's frustum planes. A mesh with `chunks` (`{first, count, box}`) draws only runs of visible chunks (`drawRuns`). The terrain builds its index buffer in 24×24-cell blocks (`terrainMesh`). Instanced props pass `{ cell, cullDist }` to `R.mesh`, which sorts instances by ground cell and re-points the instance attributes per run. Tufts are cut at `folFade[1]` and props past the fog. This took the main pass from ~2.8 M to ~0.6 M vertices and the shadow pass from 0.8 M to 0.09 M. Chunked instanced meshes must not be updated with `setInstances` (the fans aren't chunked).
- Canvas: created with `antialias: false, depth: false`. The scene always renders into our own multisampled target: the HDR one with post, or `ldr` (RGBA8 + depth MSAA) without it, resolved into a single-sample RGBA8 renderbuffer and then blitted to the canvas (a multisample blit needs identical formats and the canvas may be RGB8; a direct blit left the screen black). An antialiased canvas cost a second full-screen MSAA buffer and its resolve every frame (~0.3 ms at 2560×1600).
- Gotcha when measuring: the "Shadows" option also caps the DPR at 1.25 (game.js `resize`), so turning it off looks like it saves ~2 ms; the shadows themselves cost ~0.3 ms.
- Uber-shader lesson: any heavy code added to `LIT_FS` (even in a branch most pixels skip) raises register pressure for every lit pixel. Voronoi gravel computed in the shader plus per-pixel cloud shadows on the far mesh took the frame from 3.2 to 5.8 ms. Precompute into textures instead (the gravel now is), and measure with `gpu.py`-style throughput after each shader change.
- Frame cost at 2560×1600 on this Mac (GPU-bound; JS is 0.2–0.5 ms): Pine 3.2, Frost 3.2, Mesa 3.6, Dark Pines 3.1 ms (3.5–4.0 before this pass). Post (bloom, rays, composite, resolve) ~1.3 ms, sky ~0.45 ms, terrain 0.3–0.7 ms.
- Performance: dynamic resolution in game.js (`dyn`, judged on 1.5 s windows, scale 0.6–1, frames over 1 s ignored). At minimum scale and still under 40 fps it drops the post chain for the session (`dyn.noPost`). On SwiftShader at 1280×720 (a stand-in for a very weak GPU), culling made frames 1.4–1.85× faster and dynamic resolution + post fallback took fps from 2.7 to 4.3. MSAA 2× when the effective DPR ≥ 1.5, else 4× (`beginScene` sample hint). Bloom chain in `R11F_G11F_B10F` when renderable.
- Particles: on clean tarmac (`SURF_FX.mesa[0]`) the road dust is only a faint haze (k 0.02, alpha 0.1). Tyre smoke while sliding is a separate path. Heavier settings showed as separate grey balls behind the car on straights. `PT_VS` keeps each sprite's place on screen but depth-tests it at its front (half its size towards the camera): tested at the centre, a big dust sprite cut a hard straight line where it met the road.
- Headless screenshots: a scratch script launched Playwright with `channel='chrome'` and `--use-angle=metal` on the file:// build. That renders with the GPU, takes shots through `window.__rally` and leaves no windows open.
- Light shafts: the sky writes alpha 0 into the HDR target, so alpha marks sky vs geometry. `RAYS_FS` marches from each pixel towards the sun's screen position over that sky mask (only near the sun), at quarter resolution. The composite adds it × sun colour × `VIS[stage].rays` (forest 0.45, frost 0.45, pine 0.35, mesa 0.3), faded as the sun leaves the screen (game.js before `endScene`). It costs ~0.2 ms at 2048×1536 when the sun is in view. Don't make the sky output alpha 1 again.
- Clouds and their shadows share one field (`CLOUDS` chunk in gl.js: `cfbm`, `cbillow`, `cloudN`, `cloudUV`, `cloudLo`). The cumulus sit on a plane 900 m up, fixed in the world and drifting with the wind. The plane height doesn't change how the sky looks: it only sets their size on the ground (a few hundred metres) and the parallax as you drive. The sky samples it from the camera; the lit VS samples it from each vertex toward the sun (`v_cs`, per vertex because the field is hundreds of metres wide), so the shadow on the ground is the shadow of the cloud you see, and the sun is hidden when you stand in one. Over a run about 30% of Pine Ridge, 39% of Frostvik and 13% of Dark Pines is under cloud; Red Mesa's sparse sky leaves it clear.
- Road grain (gravel stones, tarmac aggregate, snow crust) is sampled in world space (`v_wp.xz`), ruts, cracks and patches in road coordinates: road coordinates squash the inside of a hairpin and stretch the outside. The terrain's verge tint is a narrow band (to hw + 3.2 m), or the whole inside of a hairpin turned sand-coloured.
- Gravel (`LIT_FS` mode 1, non-tarmac, non-ice): stone cells come from `gravelTex()` in world.js, a 512² RGBA8 texture (one metre of road, built once in JS, ~20 ms) with two tileable Voronoi layers: rgb = small stones (~4 cm: shade, joint mask, dome), a = bigger loose stones (~8 cm, 45 % of the cells, set apart: mask × (0.25 + 0.75 shade)). The shader reads it twice through different rotations; small stones are pressed flatter in the wheel lines, big ones only lie where the gravel is loose. The road mesh gets it as `tex`. The old value-noise blobs read as camouflage.
- Tree LOD chain: `m.lods = [{ m, dist, band }, …, { m }]` in `drawRuns`; pines full → `pineGeo(…, mid)` → `pineFarGeo` at `LOD_NEAR`/`LOD_MID` = 130/280 m, birches full → far at 150 m. Each swap is a screen-door dissolve over its band: LIT_VS passes the instance's ground distance (`v_ld`), LIT_FS discards by `hash12(gl_FragCoord)` against `u_lodB` (band below and above the level being drawn), so every pixel in a band belongs to exactly one level. The shadow pass uses the last level everywhere. Ground cover fades over 100–150 m. Cost ~+0.15 ms at 1600×1000.
- Trees (LIT_FS **mode 10**, `a2c: true`): pines are whorls of drooping needle sprays (cards, 3 segments, rolled ±40–60° alternately, normals blended towards "out and up" for volume) around a dark inner cone, from `treeAtlas()` (512²: spray u 0–0.5, bark 0.5–0.75, dense needles 0.75–1; colours near-neutral, the instance colour sets the hue; `bleedAlpha` fills transparent texels). Bark uses uv.y shifted by −2 (untinted). Back faces of sprays flip the normal (undersides in shade); Frostvik puts snow on upward faces (`u_icy`). Three shapes in `PINE_SHAPES`. Far LOD (`pineFarGeo`, >70 m) = solid ragged skirts with undersides, and `shadowDist: -1` makes the shadow pass always use it (the depth pass has no alpha test). Birches: 16 irregular leaf clumps from `leafAtlas()` + `birchFarGeo`.
- Old-growth pines (Dark Pines, tree `type: 3`; owner: "más inmersivo, árboles más altos"): `PINE_SHAPES[TALL..]` (spruce, round-crowned pine, fir) are 21–26 m before instance scale (`sy` 0.85–1.2, so ~18–31 m), crown from 7–10.5 m up (`base`), `crownR` gives the crown profile (`round` pulls its foot in). `oldTrunk`: flared foot with root lobes and a little moss, bark mapped once over the bare part and once inside the crown, dead branch `stubs`; the mid LOD uses a plain trunk. Thinner core (0.4–0.45), more branches, flatter sprays (`roll` 0.4) since they're seen from below; the lowest whorls thin out. Mid LOD from 95 m (not 130) with 45 % of the whorls. Drawn with `sway` 0.4 (the hit shake in LIT_VS now scales with `u_sway`, so other trees are unchanged). Ground shade under them ×1.3 radius, 0.36. Cost at 1600×1000: 2.46 → 2.79 ms/frame (+9 % vertices; the first try with the full mid LOD was 2.94).
- Props are rounder: `smoothGeo(g, deg)` (world.js) smooths any Geo by shared position; spectators are cylinders + spheres (`sphereGeo`), rocks are displaced icospheres (`boulderGeo`), cacti are saguaros with domed tops and elbows, arches are inflatable tubes, far mountains have 14 spokes × 6 rings with colour per vertex and the far mesh is smoothed at 72°.
- Car rear (2026-10): the livery atlas is 1024 × 1280 layout units (`AT.H`, `V(y)` for v); rows 1030–1250 are the tail panel (`uv.rear`, used by every back-facing perimeter face): the side stripes are carried round by stretching the column just ahead of the tail, the make is lettered in silver on a black garnish between the lamps (a pickup gets SAVEIRO pressed into its tailgate), shut lines, stickers and road dirt. Tail lamps are red reflector cells (the only emissive part; 0.55 by day, 0.85 with lights, 3.2 braking) with amber and clear lenses in the body mesh and a dark tinted cover in `lens`. Hatches get a rear wiper, every car a banner across the top of the rear screen.
- Car: `envRefl` reflects a broken skyline (`u_skyline`, per biome `SKYLINE`, hazed/darkened by condition) so paint shows a horizon line; side-panel triangles (`g.lock`) get a curvature field in their normals (`curveSides`), mirrors are `blob` ellipsoids, roof intakes are `scoop`s, lamps are 18-segment discs with a reflector ring, the livery is painted at 2048² (layout still in 1024 units), tyres have sidewall lettering from `tyreCanvas()` drawn with **mode 11** (vertex colour × texture).
- Composite: a light unsharp mask (skipped while the speed blur runs). Steep terrain in mode 9 gets wandering rock bands instead of smeared ground texture.
- Cost of this pass at 1600×1000 (throughput, ms/frame incl. JS): Pine 1.81→2.12, Frost 2.05→2.11, Mesa 1.89→2.10, Dark Pines 1.76→2.30.
- Lighting extras: fog with sun in-scatter (`u_glw`, the same term as the sky's horizon so there is no seam), and shade baked into terrain vertex colours under trees and rocks. Pines get a vertex-colour gradient (dark base, light tips).

## Physics (core.js)
- Two-axle bicycle model, Pacejka-lite `sin(1.45·atan(x))`, friction circle, weight transfer, downforce, turbo/boost model, gearbox from ratios + final drive, AWD split, ABS-like brake limit when steering.
- Assists, all in `TUNE`: turn-in assist, slide "hold" (yaw target), **trail braking** (`trail`, `trailK`: braking while turning brings yaw up to a grip-limited target), `lowGrip` (extra bite under ~70 km/h for hairpins), `lockK`, per-axle surface grip blend at the road edge (`edgeA/edgeB/edgeMix`).
- Slide traction (`slideA/slideB` = 0.03/0.2 rad of axle slip angle): an axle that is already sliding keeps the same lateral share as a turned wheel (`tcF/tcR`), so flooring it out of a slide pulls the car straight instead of spinning both axles up. Before this, a handbrake slide + straight wheel + full throttle took 1.1–1.3 s to grip again; now ~0.5 s. Starting the reserve at small angles (0.03) also stops the pendulum after a countersteer (Peugeot/Audi went from ~0.85 s to ~0.35 s). Normal driving, power-on oversteer and AI times are unchanged. `slideF` scales the front reserve (1 measured best).
- Spin catch (`spinK/spinB/spinV` = 5 / 0.5 rad / 12 m/s): past ~29° of slip and still rotating further into it, part of the yaw rate is bled off. It never acts with the handbrake held and only fades in above ~43 km/h, so handbrake hairpins keep their times. Measured with `human.js` over 12 aggression levels (216 runs), compared with the handling before these changes: spins 56→13, resets 32→18, hits 61→41, off-road 448→369 s, and slightly faster overall.
- **Drifting** (`node drift.js`): a driver bot holds a target slip angle (15/25/35°) with an analogue stick, a keyboard bot does the same with left/none/right and throttle on/off (20 Hz, 0.1 s lag), and a throttle test compares 0.3 vs full throttle from the same held slide. The rear's extra grip (`rearGrip` 1.08, which keeps ordinary cornering settled) used to pull every slide straight: on gravel the slides died or were lost 9 times in 21 and the throttle barely moved the angle. Now, with the tail really out (rear slip 0.15–0.32 rad), the throttle down (0.5–0.9) and the wheel turned either way, the rear grip blends to `rearSlide` 0.85 (spinning rear tyres give up side grip): gravel hold error 9.3/10.2/18.3° → 8.8/2.8/4.5°, keyboard 10.5° → 7.3°, the throttle now swings a gravel slide by +7–12°. Straight wheel + full throttle still recovers (0.62 → 0.70 s). Gating it on any steering or on countersteer alone, or starting at smaller slip, or lowering the auto-countersteer (`assist`) all made the keyboard bot spin far more (2 → 8–47), so those were dropped. Ordinary cornering metrics (`hmetrics`) are unchanged except full-lock full-throttle at 108 km/h (power slide 12–16° → 19–27°, no spins). The front wheels are drawn at the physics angle (`c.delta`, driver input + self-aligning countersteer), and a pad hums softly through slides.
- **Drifting, pass 2**: the drift bots now work the angle with the throttle (more angle wanted → more throttle, easing off only well over the entry speed), as a driver does; the old speed-holding throttle killed every shallow slide. The rear-slide blend also triggers on body slip (`rsBA/rsBB` = 0.12–0.24 rad), not only on rear-axle slip: in a shallow drift the rear axle's own slip stays under 0.15 rad, so the rear went back to full grip and straightened the car. With the corrected bots: gravel 15° slides lost 4 → 1 (of 7), keyboard 7.3° → 6.8°; tarmac keyboard 16.7° → 14.4° (lost 6 → 4); snow 0.8/1.3/4.1° and nothing lost. Recovery 0.71/0.77/0.61 s (gravel/snow/tarmac), keyboard bot over 16 levels unchanged (spins 31 → 33, resets 40 → 36). Tarmac short slides still straighten as speed builds (both axles saturated, more lock does nothing; the Quattro's nose pushes even at 25°): that is AWD on asphalt, a lift or the handbrake starts it again. A slide "memory" (rear grip returning slowly after the angle drops) was tried and changed nothing.
- **Drifting, pass 3 (owner: "un poquitito menos de drift, un poco más de control", but keep the handbrake as it is for hairpins)**: slides now come in two kinds. A slide started with the handbrake (`c.hbSlide`, set while it is held and for 0.5 s after (`c.hbT`), cleared once body slip drops under 0.08 rad) keeps the pass-2 rear (`rearSlide` 0.85, body-slip trigger 0.12–0.24 rad). A power slide without it uses `rearSlideP` 0.92 with the trigger at `rsPA/rsPB` 0.16–0.30 rad. Full lock + full throttle at 108 km/h: 23/18/28/28/30/10/14° → 14/11/21/19/16/9/10°. Keyboard bot over 2 × 16 aggression levels (0.7–1.47): spins 253 → 224, resets 262 → 237. Handbrake hairpins (`sweep.js` hpHB, `hmetrics` HB) and `drift.js` (its slides start with a handbrake tap) are identical, recovery 0.70/0.76/0.61 s, AI 70/70 clean.
- The car is placed on the road with `projectRoad` (core.js), not `project`: between two samples it interpolates along the normal lines at both ends (the lines the road mesh is built on), so `s`/`lat` are continuous. Projecting onto the polyline jumped by ~lat × turn angle per sample on the inside of tight bends (~0.2 m in a hairpin), and on a climbing road that kicked the car up at up to ~200 m/s² (Red Mesa reverse's hairpin threw it 0.33 s into the air). Now the biggest kick away from jumps is 7–22 m/s² on every stage. `project` is still used for terrain, props and ghosts.
- Keyboard steering rate depends on speed (fast at hairpin speed, gentler at high speed).
- Stages: `STAGES` in core.js; each has an `id` (saves, `VIS` palette) and a `kind` (pine/frost/mesa) that drives behaviour shared between stages: terrain shaping, tufts, dust, skid marks, surface sounds, camera roughness. **Dark Pines** (`id: 'forest'`, `kind: 'pine'`) is a narrower gravel road (hw 4.0) with rows of pines along both verges for the whole stage (`placeObjects`, ~6500 trees: about three quarters old growth, the rest young pines and a few birches that keep it closed at eye level), a needle-litter floor, a low morning sun and a green haze (`VIS.forest`, with `tuftPer`/`tuftTint` overrides).
- Frostvik's snowbanks (`st.bank` = 1.3 m past the road edge, `bankDrag` 0.9) are deep snow, not a wall (`softWalls`): the car slows the further it ploughs in, most at the bank's crest and about a third of that in the open snow beyond, but nothing pushes it back or bounces it onto the road (the old spring, up to ~13 g plus a bounce at 2.2 m, steered the car back like an invisible rail; the owner asked for it to go). At 30° into the bank at 108 km/h the car used to come out at 90 km/h pointing back at the road; now it keeps its line and drops to ~58 km/h. The AI never touches the banks (Frostvik times identical, 35/35 clean); the keyboard bot only changes at aggression ≥ 1.3, where it now loses time in the snow instead of bouncing. Red Mesa's gorge walls still use the spring.
- Impacts (`collide`): bounce with restitution, and a speed loss that scales with how square the hit is (`TUNE.impactP`; 0 = the old flat 18% on every touch). A graze along a row of trunks costs a few percent, a head-on hit still stops the car. A full rigid-body impulse (contact point, friction, inertia) was tried: it wedged the car against trunks more often (keyboard-bot resets 23→44), so it was dropped. Measured on 4 stages × 12 aggressions against the old model: resets 23→19, spins 16→14, off-road 444→408 s.
- Car specs in `CARS`. Adding a car takes a `CARS` entry (core.js), a shape in `SHAPES` and a livery `case` in carmodel.js (side + top lanes), plus `ENGINES` (worklet voice) and `VOICES` (fallback synth) entries in game.js. The Celica (`selica`, #6, `liftback` shape) was added this way; check it with sim.js and the handling scripts, which pick up every car automatically. The Peugeot (`pejo`) was tamed (370 hp, smoother boost, frontGrip/rearGrip) because the owner found it undriveable.

## Audio (game.js)
- Engine: `AUDIO_WORKLET` (registered from a Blob URL, data URL as fallback) holds two processors. `engine` is a combustion model: per-cylinder exhaust pulses shaped in crank angle (bulk + sharp blowdown front + `rasp` noise), cycle-to-cycle jitter (more on overrun), two open-pipe sections as damped feedback combs, silencer lowpass, airbox resonance + intake roar, valvetrain clatter, soft clip. Per-car character in `ENGINES` (`off`/`amp` per cylinder give the boxer burble and the five-cylinder warble). `crunch` makes stone clicks for loose surfaces.
- If the worklet can't load, the old oscillator synth (`VOICES`) is used. Turbo whistle + air rush, gear whine, tyre squeal (tonal, tarmac only) and pops/flutter run in the main graph.
- **Customisation (Car tab, sound only):** `settings.tune[carId] = { dump: 'bov'|'flutter', exhaust: 'stock'|'sport' }`, read through `getTune(id)` (default dump: flutter for cars with `VOICES[id].flutter > 0.5`, i.e. Lancia/Peugeot, else BOV). Clicking an option plays a preview on the car's own engine: `A.rev` runs a scripted blip (idle → 88 % of redline for 0.7 s → lift, `REV_T` 2.4 s) through the normal `updateAudio` path, so the dump and the exhaust crackle sound exactly as in a race. Sport exhaust overrides the `ENGINES` entry in `buildVoice` (muf ×1.22, rasp +0.1, sharp +0.06, drive +0.3, body peak −8 % freq / +2.5 dB, gain ×1.15) and crackles much more on the overrun; `A.voice.ex` makes `initAudio` rebuild the voice when it changes. Physics never reads it.
- Dump valve logic: a lift is the throttle closing from >0.5 to <0.1 within ~0.3 s (`A.thrPk`). It only vents if there is pressure to let go: `A.press` follows the boost while the throttle is held (rate 2.5/s) and bleeds off when it isn't, the throttle must have been held > 0.3 s (`held`, read before this frame resets it) and the last dump must be 0.5 s ago. So tapping W never vents; holding and lifting always does. H-pattern upshifts spend 55 % of the pressure.
- `sfx.bov`: a soft puff (650 Hz) and a broad hiss (highpass 1.7→1.1 kHz, +4 dB at 3.6 kHz), 30 ms attack, 0.3–0.7 s tail. No click and no resonant sweep: the first version had both and sounded like a whip. `sfx.flutter(amt, boost)`: compressor surge heard at the turbo inlet, built as air, not knocks: one noise source (highpass 260 Hz → lowpass whose cutoff opens 1.3→3.3 kHz with each puff → +5 dB at 1.15 kHz, plus a 520 Hz lowpassed body) under one envelope curve (`setValueCurveAtTime`, 1.5 kHz). The envelope is a soft swell × rounded pulses (`sin²(π·√phase)`, so no edges or clicks) over a floor of ~26 % (the air never stops), starting at 19–25 Hz and slowing to ~9 Hz as the wheel spins down, with ±8 % jitter per cycle; the whistle winds down to half pitch underneath, only lightly pulsed. The first version (hard 4 ms attacks, silent gaps, a resonant formant sweep per pulse) sounded mechanical, like something breaking. Offline levels per 20 ms: BOV ~0.14 peak (the owner likes it as it is), flutter ~0.11 peak, against ~0.05 of engine on the overrun in game.
- Exhaust bangs live in the engine worklet: a `pop` k-rate parameter (overrun crackle rate: 0.04 base, 0.1 with anti-lag, 0.3 sport, plus 0.6 sport / 0.25×antilag for ~1 s after a lift) turns some firings into small afterfires and some into misfires; `port.postMessage({ bang: size })` queues a big one that goes out with the next firing (anti-lag, limiter, shifts). A bang is a hard front plus a noisy tail through the same pipe combs, and part of it bypasses the silencer (`bl`). `sfx.pop` remains only for the oscillator fallback. Offline: crackle windows reach ~4× the overrun level. Harness: run the worklet in node with a stub processor that has `port = {}` and call `port.onmessage({ data: { bang } })`.
